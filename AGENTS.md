# Contributor guide

## Layout

`src/` is the Rust crate. `include/` is the installed C and C++ ABI.
`python/` contains the maturin package and the shared Python package.
`lammps/` is the loadable LAMMPS plugin. `examples/` and `tests/` hold
executable examples and integration tests. Canonical documentation lives
under `docs/orgmode/`. Files under `docs/source/` are generated by
`docs/export.el`.

## Build and test

Use Rust 1.88 or newer.

```console
cargo build --locked
cargo test --locked
cargo test --locked --features capi
cargo clippy --locked --all-targets -- -D warnings
cargo fmt --all -- --check
```

Build the maturin bindings and run their tests with:

```console
cd python
maturin develop
cd ..
python -m pytest python/tests -q --import-mode=importlib
```

## Documentation

Edit Org sources, then write the inventory before the Org export:

```console
python scripts/generate_docs_inventory.py --write
cd docs
emacs --batch -l export.el
cd ..
python scripts/generate_docs_inventory.py --check
sphinx-build -b html -n -W --keep-going docs/source docs/build
```

Never hand merge generated reStructuredText, `llms.txt`,
`llms-full.txt`, or the public API inventory. Run their generators.

## ABI changes

The ABI major stays stable for additive changes. Every additive C ABI
change sets `RGMIN_ABI_VERSION_MINOR` to the current `develop` minor plus
one in both `include/rgmin.h` and `src/ffi.rs`. Keep the ABI stamp and
baseline checks synchronized. Removing or changing an existing ABI item
requires a separately planned major version.

## Configuration types

Every public configuration struct is `#[non_exhaustive]`, implements
`Default` or has a named constructor, and provides one consuming
`with_*` setter per public field. Callers must start from `Default` or a
constructor instead of a struct literal. New fields need an
earlier behavior preserving default and a matching setter.

## Commits

Use conventional commit subjects such as `docs:`, `fix:`, `feat:`,
`test:`, `refactor:`, or `chore:`. Keep the subject at 72 characters or
less. Wrap body text at 72 characters. Explain the reason and observable
effect. Do not add trailers unless a project policy explicitly requires
one.
