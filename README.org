#+TITLE: rgmin Python bindings
#+OPTIONS: toc:nil todo:nil num:nil author:nil title:nil

The importable package is =python/rgmin/=.
=_core= is a nanobind module linked to the =rgmin= Rust staticlib
(=capi= feature).
Python calls only the C ABI in =include/rgmin.h= and the C++ wrapper in
=include/rgmin/optimize.hpp=.

=import rgmin= does not import ASE.
=rgmin.ase= subclasses =ase.optimize.optimize.Optimizer=.

* Build

1. Install a C++17 compiler, CMake, Ninja, and Rust (stable).
2. Install nanobind >= 3.1 and scikit-build-core >= 1.1.
3. From the repository root run =python -m pip install .=.
4. On a free-threaded build, =sys._is_gil_enabled()= is =False= after
   =import rgmin= (F1).
5. Regenerate the stub with
   =python -m nanobind.stubgen -m rgmin._core -o python/rgmin/_core.pyi=
   and commit it next to =py.typed=.

The cibuildwheel table builds =cp310-*=, =cp311-*=, =cp312-*=,
=cp314t-*=, and =cp315t-*=.
Platforms are manylinux_2_28 (x86_64 and aarch64), macOS 14 arm64, and
Windows AMD64.
There is no musllinux build.

* Thread safety

Each =Solver= carries an atomic claim (F3).
A second thread that enters =step= raises
=RuntimeError: Solver is in use by another thread=.
The GIL is released around =rgmin_solver_step_fg= (F4).
Callbacks go through =rgbind::trampoline= (F5).
Inputs are float64, C contiguous, and CPU, with =.noconvert()= (F6).
=rgbind::install_policy= registers =NumericalError= as a subclass of
=ArithmeticError= (F7).
The link line exports only =PyInit__core= (F9).
Sub-interpreters are unsupported.
Compile with =-ffp-contract=off=.

* Vendored header

=include/rgbind/rgbind.hpp= is a byte copy of
=bind/include/rgbind/rgbind.hpp= in OmniPotentRPC/rgpot at
=bb82209d778dbe7fe55855abee5f783708bad893=.
=.github/workflows/py-ci.yml= calls =py-rgbind-sync.yml= at that commit.

* Free-threaded CI

=py-ci.yml= calls =py-wheels.yml=, =py-freethreading.yml=, =py-tsan.yml=,
=py-typing.yml=, and =py-rgbind-sync.yml= from that same rgpot commit.
T2 passes =-DRGMIN_TSAN=ON=.
That option builds the staticlib with nightly rustc, =-Zsanitizer=thread=,
=-Zbuild-std=std,panic_abort=, and an explicit target triple.
The default Python build does not enable the Rust =par= feature.
