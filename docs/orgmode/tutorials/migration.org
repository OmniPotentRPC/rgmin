* From ASE, SciPy and eOn

The Rust default is the eOn L-BFGS cap (~EON_MAX_MOVE = 0.2~), not a line search. ~LbfgsStep::Wolfe~ opts into strong Wolfe. ~LbfgsStep::Scaled~ is ASE ~LBFGS~ with ~use_line_search=False~: shorten the step, keep the pairs.

| Call site | rgmin |
| ASE ~BFGS(atoms, trajectory=, logfile=)~ | ~rgmin.BFGS~. The initial Hessian is the identity, not ~alpha * I~. |
| ASE ~LBFGS(..., use_line_search=False)~ | ~rgmin.LBFGS~. Same length control. |
| ASE ~LBFGS(..., use_line_search=True)~ | ~rgmin.LBFGS(use_line_search=True)~, the strong Wolfe search. |
| ASE ~FIRE(dt=, dtmax=, Nmin=, finc=, fdec=, astart=, fa=)~ | ~rgmin.FIRE~. ~dtmax~ is kept. A Rust session would use ~2.5 * dt~. |
| eOn ~opt_method = lbfgs~, ~max_move = 0.2~ | ~Lbfgs::default~ or ~rgmin.LBFGS(eon_cap=True)~. |
| eOn ~cg~ | ~minimize_eon_cg~. ~Method::eon_cg~ is only the coefficient and the restart. |
| SciPy ~method="L-BFGS-B"~ | ~Lbfgs::minimize_box~ for bounds. ~LBFGSB_FTOL~ is SciPy's ~ftol~. The stop there is the projected gradient. |
| SciPy ~method="CG"~ | ~Method::polak_ribiere_plus~, ~max(0, β)~. |

~run(fmax, steps)~, ~attach~, ~trajectory~ and ~logfile~ are ASE's. The classes subclass ~ase.optimize.optimize.Optimizer~.

The nanobind classes in ~rgmin.ase~ are the drop-in for ~ase.optimize~. ASE 3.29.0's optimizer tests, parametrised over every class, live in ~tests/python/test_ase_upstream.py~. A restart file is an evaluation log (~rgmin-replay-1~). A file ASE wrote raises ~RestartError~. ~replay_trajectory~ is L-BFGS only; any other class raises ~TypeError~.

| ~rgmin.ase~ | ASE class | ~maxstep~ | Difference |
| ~LBFGS~ | ~LBFGS~ | per atom, capped eOn step | ~eon_cap=False~ selects ASE length control. ~use_line_search=True~ is strong Wolfe, not ASE ~LineSearch~. ~damping~ multiplies the cap. |
| ~BFGS~ | ~BFGS~ | per atom | ~alpha~ scales the energy so the first step is ~-g / alpha~. A pair with negligible curvature is skipped. ~maxstep > 1~ warns. |
| ~FIRE~ | ~FIRE~ | Euclidean length of the step | The session receives ~Nmin + 1~. After a downhill reset the time step is kept. ~maxmove~ warns and means ~maxstep~. |
| ~FIRE2~ | ~FIRE2~ | Euclidean, or each component with ~use_abc~ | ~dtmin~ must be ~0.02 * dt~. The position callback is accepted and not called. |
| ~QuickMin~ | ~MDMin~ | per atom | ~dt~ is the Euler step. There is no ASE velocity file to read. |
| ~CG~ and the other conjugate-gradient classes | none with that name | per atom | Not ASE's line-search CG. |
| ~SD~, ~Adam~, ~BB~, ~DIIS~, ~SR1~, ~SR2~ | none | per atom | Same log, trajectory, constraints, and cell filters as the named classes. |
| ~Newton~, ~RFO~, ~Dogleg~ | ~RFO~ only | per atom | An explicit ~hessian~ callable is required. |
| ~Optimizer~ | none | per atom | The raw session. The default method is the eOn L-BFGS step, not ASE length control. |
| ~PSO~ | none | per atom | Not a local force relaxation. The Au parity check does not use it. |

A non-positive ~maxstep~ clears the per-atom cap. On ~LBFGS~ that restores the eOn cap of 0.2. A negative ~maxmove~ turns every cap off.

The scaled step is not the one to copy when the function has a flat well. On the 10-dimensional Rosenbrock start, ASE's length control stops near ~x0 = -1~ with value about 4 and an infinity norm below ~1e-5~. The eOn cap and the Wolfe search both reach the minimum at 0. SciPy's L-BFGS-B does too. ~tests/scaled_rosenbrock10.rs~ and ~python/tests/test_ase_optimizer.py~ record that. The tolerance is the same; the step rule is what leaves the well.

~Stepper::step~ is the one-iteration seam rgsaddle already calls on ~Solver~.
