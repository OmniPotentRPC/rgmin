PRIMME, libkrylov and SLEPc are now refused with `Error::ProjectorUnsupported` when the projector is not the identity, before any backend is called. They solve the operator they are given, so a projector could leave a vertical direction as the lowest pair and return a zero vector with a stale eigenvalue. A projector that leaves no direction, or a solve whose vector vanishes under the projection, returns `Error::ProjectedSolve` instead of a zero vector or amplified rounding noise. The documentation now says which solvers honor the projector.
